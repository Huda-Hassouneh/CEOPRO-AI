## 3. Findings

### 3.1 Exposed credentials - FAIL (open, PENDING_ACTIONS #64, #75, #102)
The repository is **public**. A scan of its history (values compared, never printed) found that 16 of
the 17 credential values in the owner's current keys checklist are in git history: `JWT_SECRET`,
`POSTGRES_PASSWORD`, `APP_DB_PASSWORD`, `MINIO_ROOT_PASSWORD`, `GRAFANA_ADMIN_PASSWORD`,
`CREDENTIAL_VAULT_MASTER_KEY`, Cloudflare, Hugging Face, Gemini, Together, Horde and Pollinations
values, `GROQ_API_KEY`, SMTP login and password, and the database/Redis URLs - added between
2026-10-13 and 2026-10-19 (`KEYS_AND_ACCOUNTS_NEEDED.md`, `.env.example`, a tracked root `.env`) and
later blanked. The current tree holds none of them. Providers that scan public GitHub (Groq,
Hugging Face) revoke such keys automatically, which matches the 401s above. Every one of these
values must be replaced; removing them from history does not undo the exposure. A newer Groq key,
created after these commits, is not in the history.

### 3.2 Staging - FAIL
Checked from GitHub's network (workflow "Check competitor source links", run 39666305399,
2026-10-21 19:59 UTC): `keel-frontend-staging.onrender.com` -> 200;
`keel-ai-staging.onrender.com/health` and `/health/ready` -> no answer within 25 s.
The frontend is served, the API is not. Root cause NOT CONFIRMED (needs Render deploy/runtime
logs). Leading candidate: the three required secrets in section 1 are missing on the service - the
entrypoint applies migrations before starting the API, so it would stop at boot.

### 3.3 Paid worker in the Blueprint - FIXED (this branch)
`render.yaml` declared `keel-workers-staging` on the paid `standard` plan; a Blueprint sync would
create it. Commented out, with the deployment guide updated; the API, frontend and Redis remain
free. `yaml.safe_load` parses; `test_market_discovery.py` reads only the API service.

### 3.4 Tenant isolation - NOT TESTED
To run: two companies, every ID-taking endpoint as the other company, and a database probe as
`ceopro_app` over every table with `tenant_id`.
