# Evidence interpretation and reproduction

All records in this directory are **source evidence**, with explicit boundaries. They are not certification of a running integration. The original 66-file Phase 0 evidence is preserved in the prior archive; DOCUMENT_BASELINE_PHASE0R.json records its hashes. Raw lexical DB candidates remain RAW_PHASE0_DB_CANDIDATES.csv. The old PHASE0_VERIFICATION.json is historical, not the current file inventory.

## Trace joins

Join all atomic tables by capability_id and repo. ATOMIC_FLOW_TRACES gives the selected exact roots, current entry/UI boundary and known absent/unequal operation. SOURCE_FUNCTION_REFERENCES includes selected functions and statically followed callees; ATOMIC_CALL_EDGES retains conditional/default/callback labels rather than asserting every branch executes. Source locations include callback column positions so two inline functions on one line do not collide. CALLER_ENTRY_JOINS links selected roots back to actual mounted handler, worker/CLI or explicit non-HTTP boundary. ENTRYPOINT_REGISTRY resolves router exports and app prefixes; inactive legacy similarly named route files are not mounted simply because they exist. Middleware declaration is distinct from business activation. Declared utilities without an active caller are explicitly labeled, including the unused Node refresh token utility and Python require_entitlement helper.

FRONTEND_CONSUMER_JOINS locates symbol consumers; it is not browser execution. DTO_CONTRACT_DECLARATIONS retains full source type/schema/model definitions. DTO_SOURCE_REFERENCES binds source contract uses where verified; DTO_TOKEN_CANDIDATE_REJECTIONS records discarded unbound lexical matches and the reason they cannot establish a contract. An inline route JSON construction is also described by return keys and exact source function; finding a type is not proof it is the response for every transitive route. ATOMIC_FAILURE_AND_STATE_FACTS retains exact source-line transaction, raise/throw, lease/reservation/release and state transitions; not every listed statement runs on every invocation. EXTERNAL_BOUNDARIES names SDK/model/socket/driver/default-injection edges and next validation, without inspecting credentials or calling providers.

## Schema joins

SCHEMA_DDL_OBJECTS and SCHEMA_COLUMNS are source-history records with source line, statement and operation, not the live effective catalog. SCHEMA_LINEAGE_<FAMILY> adds per-family scope including shared tenant/auth functions and conditional policy templates. Prisma mappings retain mapped names. SQL_ACCESS_SOURCE_FACTS joins table references and ORM delegates to actual DDL identities; relations/conditional branches require actual SQL/runtime verification. Dynamic SQL obligations are retained individually rather than inventing executed policies or effective ownership. No lexical import token is promoted to a table.

Extraction used TypeScript 5.9.3 AST/module/import resolution and TypeChecker symbol binding for contract uses (Python local/exact import model binding), Python AST and pglast 8.7 (PG18 grammar), plus source review of selected roots and 12 source corrections. Versions were installed only in scratch. Parser success is not PG17 compatibility. No repository dependency or lockfile changed. Generators are discovery tools; ambiguous calls and conditional SQL do not acquire runtime certainty from graph reachability.

## Reproduce the bounded verifier

Run `python docs/keel-integration/evidence/phase0r/verify_phase0r.py --python-root <absolute Python root> --node-root <absolute Node root>` (optionally `--write-result` for the document JSON). This hashes every original source, validates actual paths/lines, stable identifiers/coverage, real DDL table identities, 13 pending decisions, relative links, actual Git document inventory and incremental ledger against the preserved 66-file document manifest. It performs no network/database/provider operations. GIT_DOCUMENT_DIFF_PHASE0R.txt records normalized output from actual `git diff --no-index --name-status` against the reconstructed and hash-checked prior documentation tree; it avoids staging or committing the dirty incoming working tree. Source manifest and reviewed clean-commit status remain separate checks.
