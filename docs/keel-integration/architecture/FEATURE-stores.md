# Feature architecture — stores

Status: PROPOSED for architecture review; capability families STORE SHOP WOO. Single Python authority is already approved by user; no conflicting policy is selected.


Actual Node path: ConnectDataPage → `/data-connection/store/*` (dataconnection.route mounts store router after authentication/tenant) → storeContext active owner/admin + tenant/data_integration rights → connections.repo (source-slot lock/verified provider) or Shopify OAuth → encrypted credentials → store_connections → store-connectors.worker.ts restricted scheduler/app roles → claimStorePage → provider.client signed internal body-hash token → read-only Node ai/connectors/app.py → Shopify/Woo provider transport → syncStorePage → canonical products/inventory/invoices/transactions plus external link/audit rows → checkpoint/status/API UI. This is more than the generic Python REST connector.

Python destination has no dedicated adapters or mounted OAuth/store endpoints in the supplied graph. Reuse onboarding/data_sources/vault/jobs/core usage/promotion and existing worker registrations. Proposed adapters live under `src/market_scraper/connectors/`, store lifecycle under `src/ai/stores/`, route under routers/store_connections.py. Pure normalization can be adapted from read-only ai/connectors, but that subtree is never edited and its service is not retained as a second required authority. The internal Node adapter JWT is not a customer identity contract to port wholesale.

Shared durability: port claim/fetch/commit fencing: lock connection in tenant transaction, verify source/status/capacity; create or resume job; lease token 120 seconds and connection version; commit; provider request outside DB transaction; validate contract version and each item; new transaction rechecks lease/version/source status and access; atomically commit page, lineage and progress. Incremental sync fixes an until bound, overlaps prior success by five minutes, and rejects non-progress pages/cursors; retries bounded (Node attempts<5, exponential up to 3600s). These are source defaults, not newly approved commercial monitoring cadence. Disconnect/uninstall increments version and removes secrets/fences stale work; cleanup is allowed without granting data access.

Shopify: OAuth begin/complete callback-ticket flow binds HMAC-verified callback, unique state/nonce/tenant/shop/expiry, scope checks and shop identity. Raw callback verifier rejects duplicate query keys and >600s timestamp drift. Token rotation supports access/refresh expiry and reconnect. GraphQL bounded variants, inventory locations and nested order lines; approved scopes/historyAccess recent vs all, includeTestOrders policy; shopMoney exact Decimal normalization. Signed raw-body webhooks verify HMAC, bind topic/shop/event, cap IDs and dedupe delivery. Topic set: app/uninstalled; products/create/update/delete; orders/create/updated/paid/cancelled; refunds/create; inventory_levels/update; customers/data_request/redact; shop/redact. Required scopes and API version stay explicit in adapter configuration and live certification; do not infer platform approval from local code.

Node Shopify SQL process_shopify_event executes under restricted SECURITY DEFINER ownership, schedules resync, revokes connections on uninstall, persists privacy requests/exclusions/reports and owned source effects. Port intent into Python with audited grants and fixed search_path, not wholesale all-tenant privileges. Privacy retention/deletion across canonical business invoices and manually shared products requires PRIVACY-001.

WooCommerce: verified HTTPS shop URL, public target/DNS pinning and redirect refusal; REST credential verification and vault storage; simple/variable products with normalized stock, variations and barcodes; order pagination with modified-time overlap/exclusions; explicit order status whitelist and refund allocations. It rejects ambiguous amount-only refunds or inconsistent total equations rather than inventing sales/stock allocations. Retain those rejection semantics and operator-visible retry/quarantine state. No OAuth install requirement is invented for Woo: source uses REST keys.

Canonical writes: external source/product/variant and order/item IDs map to existing Python product/inventory/invoice/transaction IDs. Preserve ownership flags so curated/shared data is not deleted/overwritten. Refund/cancel correction updates linked sale/invoice projections once; invoice tax/shipping/discount/fees/duties use verified provider normalization, not flattening all totals into product revenue. Location stock writes and order sales must not subtract stock twice. IMPORT-001 resolves competing source ownership, grouping and replay across manual imports.

UI: add provider-specific connection forms, OAuth completion and scoped permissions, real queued/verified/sync/error/disconnected status, reconnect/retry, job/detail history and privacy report views using existing React Query/API conventions; no credentials returned in responses. Credential, source-capacity, invalid-signature/state, pagination, monetary, stale-lease and privacy tests are required before enabling provider collectors. Live development store/sandbox certification remains blocked without authorized test resources.
