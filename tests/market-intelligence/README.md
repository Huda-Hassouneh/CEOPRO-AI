# Market Intelligence diagnostics

This suite reuses the Dashboard Playwright configuration, PostgreSQL read-only/RLS helper, and structured diagnostics reporter. It calls the real backend and frontend; the deterministic overview test does not mock the Market Intelligence API.

## What the current UI exposes

`MarketIntelligenceOverviewPage` (`/market`) displays four metrics, AI Market Intelligence insights, a competitor table, pricing recommendations, expansion opportunities, and recent price changes. It has product and 30/90 day period filters, a pricing recommendation action, per-section PDF exports, loading/error/empty states, and Arabic/English formatting. Other market routes (competitors, trends, reports, opportunities, leaderboard) exist separately; this suite is scoped to the overview flow and only tests controls exposed there.

The frontend route is gated by `market_intelligence`. The backend overview route currently applies authentication and tenant validation but does not call `requireEntitlement("market_intelligence")`. The overview also calls MPI enrichment directly without checking the separate `market_perception` entitlement; the standalone MPI route has its `requireFeatureAccess("market_perception")` middleware commented out. AI Pricing is a separate entitlement too, and the pricing route has its `requireEntitlement("ai_pricing")` middleware commented out. Regression assertions intentionally fail for these source-level gaps; no subscription policy or application code was changed as part of this test work.

## Metric → calculation → tables → producer → UI

| UI value / section | Current source and calculation | Producer / backend path | UI behavior |
|---|---|---|---|
| Total Competitors | Count active `competitor_product_mappings` for selected product whose `tenant_competitors.is_tracked` is true. A price is not required. | Discovery/manual mapping → `competitor_product_mappings`; GET `/market-intelligence` → market-intelligence repo. | Number; competitor table can show rows with no price and marks those unavailable. |
| Average Price Score | Per active tracked mapping, use latest in-period `competitor_prices` where available, exact, source `ALLOWED`, same currency as product. Score = clamp(`10 - abs(1 - ownPrice / competitorPrice) * 10`, 0, 10). Round mapping score to one decimal, average eligible scores, then round API metric to one decimal. | AI market scraper or manually approved price persistence → `competitor_prices`; backend derives score. | Displayed `/ 10`; missing eligible price yields `—` for row and is excluded from average. |
| Average Composite Score | Latest `competitor_score_snapshots` row per mapped competitor, ordered by calculated time then score id; average non-null `composite_score`. Source scale is 0–100, not 0–10. | AI scraper analysis/intelligence worker writes snapshots; backend reads them. | Displayed `/ 100`; missing snapshots are excluded and empty average is `—`. |
| Top Segment Score | Segment = localized product category (English label canonical when present). Demand is summed from non-negative future forecasts, latest per product/window, normalized across distinct unequal segments to 0–10. Sentiment uses allowed/safe reviews in selected period, clamps each result to [-1,1], averages then maps to 0–10. Pricing uses latest eligible same-currency price per mapping and the pricing score above. Weighted 50/30/20; missing signal weights are renormalized. One segment or tied demand provides no demand signal. Highest score wins, English label breaks ties. | AI forecasting → `demand_forecasts`; AI sentiment → `sentiment_results`; scraper → `competitor_prices`; backend derives segment. | Displayed `/ 10`; no eligible signals produces `—`. |
| Competitor comparison | Product mappings and tracked tenant relationship; latest eligible price as above; latest score snapshot; relevance from snapshot or `product_match_rate * 100`. | AI discovery / scraper / scoring producers; GET overview. | Pricing `/ 10`; composite, relevance, presence, and perception `/ 100`; absent values render `—`. |
| Market insights | Locally derived from tenant `transactions`, allowed/safe `reviews` + `sentiment_results`, mapped `competitor_prices`, and `market_events` during period. It is not generated by an AI API in this overview method despite the response key name. | Backend calculation from AI- or user-produced rows. | Insight text and evidence drivers; no signal means empty state. |
| Expansion opportunities | For other active products, compare transaction units in current and preceding equal periods. Include only positive prior units and growth; rank by rounded growth descending; return at most three. It explicitly says this is a signal, not a market forecast. | Product transactions → backend calculation. | Opportunity cards; empty state if no qualifying products. |
| Recent Price Changes | Two latest eligible exact, available, allowed, same-currency observations per active tracked mapping in range; show only unequal values. | Market scraper persistence → `competitor_prices`; backend derives delta. | Change table; empty state if no qualifying pair. |
| Overview pricing row | Derived median of eligible same-currency prices in the selected period; action raise/reduce only outside ±10%, suggested price at 95%/105% of median. This is a backend algorithmic row, not an AI result. | Backend derives from `competitor_prices`. | Initial pricing table. |
| Generated pricing recommendation | UI POSTs `/features/pricing/recommend?product_id=...`. Backend loads tenant product, up to 30-day eligible same/cross-currency observations and exchange rates, calls Gradio `recommend`, then persists `evidence_records` and `recommendation_outcomes` and increments `ai_pricing` usage. | AI response is persisted by backend. No discovery/scraper worker is triggered by this button. | Shows recommendation result or error toast. The backend route currently has its `ai_pricing` entitlement middleware commented out. |
| Market Perception Index | Per competitor, backend calls shared Gradio `market_intelligence` through MPI service using eligible analyzed reviews; period filter is not passed. Low sample/unavailable/error returns null. | AI MPI response; backend may save evidence. Runtime service availability is external. | Qualitative positive/neutral/negative badge and 0–100 score; unavailable renders `—`. |
| PDF | Client side React-PDF export uses currently displayed section data, locale, and selected period. | Frontend only; no new DB producer. | Download per section; tests can verify PDF signature/download when configured browser is available. |

## Source ownership and runtime status

| Data producer → trigger | Destination | Backend/UI consumer | Classification / limitation |
|---|---|---|---|
| Market scraper discovery (`src/market_scraper/discovery.py`, discovery/connector workers) → worker/queue workflows | Tenant competitor records, `data_sources`, `competitor_product_mappings` | Market-intelligence repo and competitor API | AI direct PostgreSQL writes. No backend HTTP trigger was found for safe end-to-end discovery. Execution is not implied by worker presence. |
| Approved source collection (`src/market_scraper/worker.py`, collectors/persistence) → configured worker job | `competitor_prices`, `market_observations`, `market_events`, audit/staging records; price writes are subject to source policy and validation | Overview comparisons, price history, derived insights | AI direct PostgreSQL writes. Requires approved source, mapping, worker/queue, and credentials as applicable; not runtime-verified here. |
| Competitor analysis (`src/market_scraper/intelligence.py`, analysis worker) → analysis work | `competitor_score_snapshots` | Average composite score and competitor table | AI direct write. 0–100 snapshot input; job execution is not proven by code presence. |
| Sentiment (`src/ai/sentiment/pipeline.py`) → sentiment worker/pipeline | `sentiment_results`, evidence | Segment score, market insight, MPI input | AI direct write; requires eligible `reviews` first. |
| Demand forecasting (`src/ai/forecasting/pipeline.py`) → forecast consumer/pipeline | `demand_forecasts`, evidence | Top Segment demand signal and separate forecasting screens | AI direct write; future coverage must overlap the query window. |
| MPI (`src/ai/mpi/pipeline.py` via Gradio/shared client) → GET overview enrichment | MPI response; backend evidence path | Competitor perception fields | External response, not a scraper job. Optional failures are swallowed and become unavailable values. |
| Pricing recommendation (`src/ai/pricing/pipeline.py` via Gradio; CEOPRO route sends request) → explicit UI POST | Backend `evidence_records`, `recommendation_outcomes` | Pricing recommendation row | AI response persisted by backend; live test is opt-in because it may consume provider resources and writes test DB rows. |

The available source code and report files do not prove any of these workers ran successfully in this environment. The tests report database/API/UI state only.

## Test layers and safe setup

- `tests/contracts/market-intelligence-contract.test.mjs`: static route, entitlement, format, API, and UI contracts. It includes a deliberate backend entitlement regression assertion and currently reports that defect.
- `tests/e2e/market-intelligence/overview.spec.ts`: authenticated API + actual UI + independently calculated read-only PostgreSQL checks. Uses the existing `DashboardDatabase`, its test-database-name guard, non-superuser/non-BYPASSRLS guard, and `set_config` tenant/user context. It creates/deletes no rows.
- `tests/e2e/market-intelligence/live-ai.spec.ts`: explicit opt-in for the real pricing recommendation endpoint. It first proves the product is visible through the dedicated test DB/RLS context, then checks the returned evidence/outcome IDs exist for the same tenant. It does not trigger market scraping or discovery.

Configure from PowerShell in `backend`:

```powershell
$env:MARKET_INTELLIGENCE_TEST_ACCESS_TOKEN = "<test-tenant-access-token>"
$env:MARKET_INTELLIGENCE_TEST_TENANT_ID = "<test-tenant-uuid>"
$env:MARKET_INTELLIGENCE_TEST_USER_ID = "<test-user-uuid>"
$env:MARKET_INTELLIGENCE_TEST_DATABASE_URL = "<connection-string-to-dedicated-test-db>"
$env:MARKET_INTELLIGENCE_TEST_API_URL = "http://127.0.0.1:5000"
$env:MARKET_INTELLIGENCE_TEST_FRONTEND_URL = "http://127.0.0.1:5173"
npm run test:market-intelligence
```

The database name must clearly contain `test`, `testing`, `qa`, or `e2e`; production mode, superuser, and BYPASSRLS connections are rejected. Do not point this at Render production. To test cross-tenant product filtering, also set `MARKET_INTELLIGENCE_TEST_OTHER_TENANT_PRODUCT_ID` to a known product UUID from a separate test tenant. To run the Starter entitlement regression, set `MARKET_INTELLIGENCE_STARTER_ACCESS_TOKEN` to a disposable Starter tenant token.

The live pricing call is deliberately opt-in:

```powershell
$env:MARKET_INTELLIGENCE_RUN_LIVE_AI = "1"
$env:MARKET_INTELLIGENCE_LIVE_AI_PRODUCT_ID = "<product-uuid-in-the-dedicated-test-tenant>"
npm run test:market-intelligence:live-ai
```

This creates recommendation/evidence rows and consumes `ai_pricing` usage in the dedicated test tenant. A scraper/discovery live E2E remains blocked until a supported bounded trigger and job status contract are exposed; tests do not invent or invoke a worker trigger.

Inspect `metric-check`, `database-result`, `api`, `filter-check`, and `failure-category` annotations for expected/actual data and next diagnostic owner.

## Current coverage and known limitations

| Scenario | Status in this implementation |
|---|---|
| Total competitor count, average price score, composite score | Independent RLS-scoped DB comparison; requires env and current eligible data. |
| Segment score | Scale/range and availability checked in E2E; source formula is documented above, but no synthetic DB fixture suite was possible without a dedicated seeded DB. |
| Product and 30/90 day period filters | Browser/API interaction checks; requires frontend/backend. |
| Arabic rendering | RTL and Arabic label check. |
| Missing competitor price | API row must remain present and show unavailable; needs a fixture tenant with such a mapping to exercise. |
| Empty products / missing score snapshots / missing sentiment or forecast | Behavior is documented; current read-only E2E checks empty-product branch, but does not manufacture these states. |
| Cross-tenant | Optional other-tenant product probe. |
| Starter entitlement | Regression check is opt-in and intentionally fails against the current unguarded backend route. |
| Generated AI pricing | Explicit live test only; no default provider call. |
| Discovery/scraper/scoring workers | No safe backend trigger/job contract found; blocked and not claimed as verified. |
| PDF export | Overview E2E downloads one real section report and checks the PDF signature and nontrivial size; text/section/currency/Arabic extraction checks remain unverified. |
